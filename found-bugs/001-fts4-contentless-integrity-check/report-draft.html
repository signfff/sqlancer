标题 · Subject

PRAGMA integrity_check fails on every contentless FTS4 table since 3.44.0

正文 · Body（Markdown）

Since 3.44.0, `PRAGMA integrity_check` and `PRAGMA quick_check` report an error for every contentless FTS4 table, even an empty one that has never been written to. 3.43.2 reports "ok" for the same database.

```
CREATE VIRTUAL TABLE a USING fts4(x, content='');
PRAGMA integrity_check;
-- 3.43.2:          ok
-- 3.44.0 .. trunk: unable to validate the inverted index for FTS4 table main.a: SQL logic error
```

A database file created and checked with 3.43.2 ("ok") fails integrity_check as soon as it is opened with 3.44.0 or later, with no change to the file. MATCH queries on it keep working.

Controls, all "ok" on every version tested: an ordinary FTS4 table, an external-content FTS4 table over a real table (`content='src'`), and a contentless FTS5 table (`content=''`).

fts3IntegrityMethod(), added with xIntegrity in 3.44.0, calls sqlite3Fts3IntegrityCheck(), which prepares `SELECT ` against the content table. A contentless table has no content table, and the resulting SQLITE_ERROR is reported as an integrity problem. The FTS4 'integrity-check' command (`INSERT INTO a(a) VALUES('integrity-check')`) fails the same way, and did so before 3.44.0, but it only runs when asked for. FTS5 skips the content comparison for contentless tables and returns "ok".

Section 6.2.1 of the FTS3/FTS4 documentation lists the operations contentless tables do not support, and integrity checking is not among them. The virtual table documentation says xIntegrity reports problems with the content of the table, and the content here is fine.

This looks like a sibling of the read-only case fixed in b855886c4c ("Ensure xIntegrity methods of fts3/fts5 work on read-only databases"): another healthy FTS4 configuration that the 3.44.0 xIntegrity method does not handle.

Versions tested:

- 3.43.2 2023-10-10 4310099cce: ok
- 3.44.0 2023-11-01 17129ba1ff: error
- 3.53.4 2026-07-24 bf7c7f3003: error
- 3.54.0 trunk 2026-10-01 16:48:03 99aab2c992: error

English (posted)中文（对照理解用，不要发）
Summary

Since 3.44.0, PRAGMA integrity_check and PRAGMA quick_check report an error for every contentless FTS4 table, even an empty one that has never been written to. 3.43.2 reports "ok" for the same database.

概述

从 3.44.0 开始，PRAGMA integrity_check 和 PRAGMA quick_check 对每一张无内容 FTS4 表都会报错，即使是一张从未写入过的空表。同一个数据库在 3.43.2 上返回 "ok"。

Reproducer 
CREATE VIRTUAL TABLE a USING fts4(x, content='');
PRAGMA integrity_check;
-- 3.43.2:          ok
-- 3.44.0 .. trunk: unable to validate the
--   inverted index for FTS4 table main.a:
--   SQL logic error
复现

建一张无内容 FTS4 表（content='' 表示只存倒排索引、不存原文），然后体检。3.43.2 返回 ok；3.44.0 到最新 trunk 都报"无法验证 FTS4 表 main.a 的倒排索引：SQL logic error"。

Upgrade

A database file created and checked with 3.43.2 ("ok") fails integrity_check as soon as it is opened with 3.44.0 or later, with no change to the file. MATCH queries on it keep working.

升级场景

用 3.43.2 创建并体检通过（ok）的数据库文件，一旦用 3.44.0 或更新版本打开，体检就失败，而文件本身没有任何改动。在这个库上做 MATCH 全文检索仍然正常。

Controls

Controls, all "ok" on every version tested: an ordinary FTS4 table, an external-content FTS4 table over a real table (content='src'), and a contentless FTS5 table (content='').

对照组

以下三种表在所有测试版本上体检都是 ok：普通 FTS4 表；以一张真实表为外部内容的 FTS4 表（content='src'）；无内容 FTS5 表（content=''）。这说明问题只出在"无内容 + FTS4"这个组合上。

Cause

fts3IntegrityMethod(), added with xIntegrity in 3.44.0, calls sqlite3Fts3IntegrityCheck(), which prepares SELECT <zReadExprlist> against the content table. A contentless table has no content table, and the resulting SQLITE_ERROR is reported as an integrity problem. The FTS4 'integrity-check' command (INSERT INTO a(a) VALUES('integrity-check')) fails the same way, and did so before 3.44.0, but it only runs when asked for. FTS5 skips the content comparison for contentless tables and returns "ok".

原因

3.44.0 随 xIntegrity 接口加入的 fts3IntegrityMethod() 会调用 sqlite3Fts3IntegrityCheck()，后者要对内容表执行 SELECT …，把原文重新分词后和倒排索引比对。无内容表没有内容表，这一步失败产生的 SQLITE_ERROR 被当成了体检问题上报。FTS4 自带的 'integrity-check' 命令也以同样方式失败，3.44.0 之前就是这样，但它只在用户主动执行时才会运行。FTS5 遇到无内容表会跳过与原文的比对，所以返回 ok。

Docs

Section 6.2.1 of the FTS3/FTS4 documentation lists the operations contentless tables do not support, and integrity checking is not among them. The virtual table documentation says xIntegrity reports problems with the content of the table, and the content here is fine.

文档依据

FTS3/FTS4 文档 6.2.1 节逐条列出了无内容表不支持的操作（UPDATE、DELETE、读取原文列、snippet、offsets），完整性检查不在其中。虚拟表接口文档规定 xIntegrity 用来报告表内容的问题，而这里的内容并没有问题。

Precedent

This looks like a sibling of the read-only case fixed in b855886c4c ("Ensure xIntegrity methods of fts3/fts5 work on read-only databases"): another healthy FTS4 configuration that the 3.44.0 xIntegrity method does not handle.

先例

这和已在 b855886c4c 修复的只读库问题（"确保 fts3/fts5 的 xIntegrity 在只读数据库上可用"）属于同一类：都是 3.44.0 的 xIntegrity 没有照顾到的一种健康 FTS4 用法。那个问题在论坛报告当天就修复了，并回补到了 3.45 分支。
